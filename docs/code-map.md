README 头图由 [独立 React/SVG 工程](hero/README.md)生成：`scene.jsx` 负责构图，`TechText.jsx` 负责字形与固定 OS 选框，`HarnessCorner.jsx` 绘制应用局部；渲染与编码生成 `docs/assets/readme-hero.gif` 和静态 PNG。

## 目录地图

Pi 进程入口由 [启动器](../scripts/start-pi-runtime.mjs) 选择；Windows 直接用 Node 加载 SDK 的 JavaScript CLI，不加载 npm 的 `pi.cmd` 批处理包装。回归见 [入口与参数传递](../test/pi-launcher-entry.test.js)及[真实 CLI 会话续接](../test/cli-session-resume.test.js)。该修复不代表全部 Windows 能力已通过验收。

```text
scripts/install.sh         CLI 安装：公开发行版、下载校验、用户目录与 PATH
scripts/atria.mjs          用户 CLI 启动器：init、doctor、start 等命令
src/cli/                  可执行入口和真实模型 smoke
src/domain/               Task、Run、Watch、Experiment、Virtual Agent 类型
src/runtime/              Pi 会话、委派、恢复、Inbox、checkpoint、长期运行
src/tools/                文件、命令/jobs、Web 等运行时工具
src/workspace/            Task 工作区、附件、产出物、项目与全局会话索引
src/storage/              JSONL 事件、trace、文件锁
src/dashboard/            本机 HTTP/SSE、路由、服务装配、Main 进程生命周期
src/applications/         应用注册、实例、资源、revision、绑定、Adapter、MCP
src/applications/plugins/ 外部 MCP 驱动的 harness 插件（FreeCAD / Blender / CAD / OfficeHarness）
src/software/             CAD、Blender、PPTist 领域实现与异步软件协议
src/gui/ + src/security/   Computer Use、原生驱动、执行权限
.pi/extensions/           Pi 薄入口
.pi/runtime/              Pi 生命周期装配、应用桥接、分领域工具
.pi/skills/               随产品交付的技能与参考资料
web/                      原生 ES modules：页面装配、控制器、工作台、领域 UI
desktop/                  Electron 主进程、可信 preload、模型加密、退出保存
test/                     Node 行为/协议/生命周期回归；p0/p1/p2 为编译后测试
e2e/                      Chromium 与独立 Electron 用户流程
scripts/                  构建、打包、开发启动、测试与文档检查
vendor/pptist/            第三方 PPTist 源码；不要混入 harness 通用职责
docs/                     用户指南、开发约定与接口参考
```

CLI 一条命令安装由 [install.sh](../scripts/install.sh) 负责，使用公开更新清单、校验后的发行包和用户目录。安装与拒绝路径见 [安装回归](../test/install.test.js)，运行 `node --test test/install.test.js`。

`src/cli/` 不存放可复用的 HTTP 或 MCP 业务实现。HTTP 帮助函数在 `src/dashboard/`，MCP HTTP 客户端在 `src/applications/mcp/local-api-client.ts`。构建输出在 `dist/`、`build/`、领域 UI 的 `generated/` 和 `.tmp/`；从源文件修改后重新构建。`build/` 中的桌面图标由 [图标构建脚本](../scripts/build-desktop-icon.mjs) 从 [原始标志](../web/assets/atria-symbol.png) 和 [Swift 渲染器](../scripts/render-desktop-icon.swift) 生成，供开发 App 和打包使用，不手工维护或提交生成副本。

## 三种常见修改流程

### 修复一个用户流程

从复现对应的 `e2e/` 或协议测试进入，沿请求或事件找到状态负责人。在负责人中修复语义，路由只调整字段/状态码映射，UI 只调整展示/交互。补一个能复现原失败的回归，再运行本页相关测试和 `npm run verify`；改变 UI 还运行相应浏览器用例。

### 接入一个新应用或工具

先确定资源格式、revision、取消和失败保证，再实现 Adapter/软件驱动、能力发现和领域工具；最后接工作台注册与 UI。共享协议归 `applications/types.ts` 或 `software/contracts.ts`，HTTP/Agent/UI 共用同一操作语义。遵循 [软件接入流程](software-integration.md)，验证 Agent 首轮发现、人工与 Agent 并行写入、冲突保留草稿和保存重开。

### 拆分一个大模块

先识别纯状态转换、存储、进程所有权和展示各自负责的行为，保持现有导出/数据格式/入口不变，一次迁移一个职责并更新消费者。新增模块不反向导入装配层；用 [边界回归](../test/architecture-boundaries.test.js) 和原行为测试验证。验收应检查依赖方向和恢复行为。

职责主责角色见 [所有权表](module-ownership.md)。根目录与各目录的 `AGENTS.md` 是修改约束；本页提供功能与测试的查找线索。

## 长期目标与监控

目标类型与版本规则在 [goal](../src/domain/goal.ts)，[GoalStore](../src/runtime/goal-store.ts) 负责加锁持久化，[GoalManagement](../src/runtime/goal-management.ts) 负责创建/修改/交接/控制，[GoalSupervisor](../src/runtime/goal-supervisor.ts) 负责恢复副作用与到期投递；[活动存储](../src/runtime/goal-activity-store.ts)、[决策恢复](../src/runtime/goal-decisions.ts) 和 [有界上下文](../src/runtime/goal-context.ts) 分别维护通知、人工问题与工作记忆。Pi [目标工具](../.pi/runtime/tools/goals.ts) 与 Dashboard [服务](../src/dashboard/goal-service.ts)/[路由](../src/dashboard/goal-routes.ts) 共用业务规则；不得从前端或模型直接改内部目标/Inbox 文件。先复核 [目标状态与恢复](../test/long-term-goals.test.js)、[真实 Pi 工具](../test/goal-tools.test.js)，同步 [目标架构](long-term-goals-architecture.md) 与 [API](product-api.md#long-term-goals)。

[交接归属](../src/runtime/goal-delegation.ts) 由 GoalManagement 写入当前用户请求，WatchManagement 的标准创建和自定义激活共同检查；[请求边界](../src/runtime/goal-delegation-request.ts) 从已交付用户消息恢复身份，同一请求重试不能省略 programId 创建替代采集器，同一 Run 的新用户请求保持独立。Main 请求快照保留重放归属。先验证 [归属回归](../test/goal-delegation.test.js)、[真实 CLI 新请求](../test/goal-delegation-cli.test.js) 与普通会话的 [创建/复用浏览器链路](../e2e/long-term-goals.spec.js)。

[目标消息路由](../src/runtime/goal-routing.ts) 区分采样与模型复盘时钟，供 Pi 停泊工具和 Supervisor/Inbox 交付共同使用；会话内目标由 `sleep_until(programId=...)` 明确归属，保留共享会话的独立及未带归属的旧时钟。后台目标的旧轮询不再空唤醒 Main，显式复盘由 GoalSupervisor 投递。复核 [停泊工具](../test/main-sleep.test.js) 和 [目标恢复](../test/long-term-goals.test.js)。

[WatchManagement](../src/runtime/watch-management.ts) 共用模板创建/激活，[ScriptWatcher](../src/runtime/script-watcher.ts) 与 [隔离 worker](../src/runtime/script-watcher-worker.ts) 执行探针，[WatchSupervisor](../src/runtime/watch-supervisor.ts) 和 Dashboard [watch-service](../src/dashboard/watch-service.ts) 分开推进采样、分析和 Main 唤醒。[monitoring-control](../src/runtime/monitoring-control.ts) 统一有效暂停意图，覆盖旧记录、启动、Inbox、注册与控制；[Main 生命周期](../src/runtime/watch-main-lifecycle.ts) 保持暂停/结束优先。先验证 [暂停](../test/monitoring-pause.test.js)、[可靠性](../test/watch-reliability.test.js)、[采样活性](../test/watch-sampling-liveness.test.js)、[恢复](../test/watch-supervisor-recovery.test.js) 与 [分类](../test/watch-classification.test.js)，按 [暂停契约](monitoring-pause-contract.md) 复核所有消费者。
