## Directory map

The [Pi launcher](../../scripts/start-pi-runtime.mjs) selects the process entry. On Windows, Node loads the SDK JavaScript CLI directly rather than npm's `pi.cmd` batch wrapper. Regressions cover [entry and argument forwarding](../../test/pi-launcher-entry.test.js) and [real CLI continuation](../../test/cli-session-resume.test.js). This fix does not establish complete Windows support.

```text
scripts/install.sh         CLI installation: published release, verification, user prefix and PATH
scripts/atria.mjs          User CLI launcher: init, doctor, start, etc.
src/cli/                  Executable entrypoints and real-model smokes
src/domain/               Task, Run, Watch, Experiment, Virtual Agent types
src/runtime/              Pi sessions, delegation, recovery, inbox, checkpoints, supervision
src/tools/                Files, commands/jobs, Web and other runtime tools
src/workspace/            Task workspaces, inputs, artifacts, projects and global catalogs
src/storage/              JSONL events, traces and file locks
src/dashboard/            Local HTTP/SSE, routes, composition, Main process lifetime
src/applications/         Registry, instances/resources, revisions, binding, adapters, MCP
src/applications/plugins/ External MCP harness apps (FreeCAD / Blender / CAD / OfficeHarness)
src/software/             CAD, Blender, PPTist domains and async software protocol
src/gui/ + src/security/   Computer Use, native drivers and execution grants
.pi/extensions/           Thin Pi entry
.pi/runtime/              Pi lifecycle composition, application bridge, domain tools
.pi/skills/               Product skills and reference materials
web/                      Native ES modules: composition, controllers, workbench, domain UI
desktop/                  Electron main, trusted preload, encrypted settings, exit saving
test/                     Node behavior/protocol/lifecycle; compiled p0/p1/p2 tests
e2e/                      Chromium and isolated Electron user flows
scripts/                  Builds, packages, dev launchers, tests and documentation gates
vendor/pptist/            Third-party PPTist source; keep harness business code elsewhere
docs/                     User guides, development conventions and API references
```

The [CLI installer](../../scripts/install.sh) uses the public update feed, verified release archives and a user prefix. Run `node --test test/install.test.js` for its [installation and rejection tests](../../test/install.test.js).

Reusable HTTP/MCP behavior does not belong in `src/cli/`. HTTP helpers live under `src/dashboard/`; MCP HTTP client lives at `src/applications/mcp/local-api-client.ts`. Build outputs are `dist/`, `build/`, domain UI `generated/` and `.tmp/`; edit source and rebuild. Desktop icons in `build/` are generated by the [icon build script](../../scripts/build-desktop-icon.mjs) from the [source mark](../../web/assets/atria-symbol.png) and [Swift renderer](../../scripts/render-desktop-icon.swift). Development apps and packages consume them; do not maintain or commit generated copies.

### Project experience and personal memory

Project experience separates [domain records](../../src/domain/project-experience.ts), [storage and private skill publication](../../src/runtime/project-experience-store.ts), [persisted execution evidence](../../src/runtime/project-experience-evidence.ts), [extraction and independent review](../../src/runtime/project-experience-learning.ts), and [bounded foreground context](../../src/runtime/project-experience-context.ts) from personal memory. Validate [identity, promotion and rollback](../../test/project-experience-store.test.js), [fake-provider evidence and lifecycle](../../test/project-experience-learning.test.js), and [real Pi isolation](../../test/project-experience-pi.test.js).

The project edit dialog uses its own [controller](../../web/assets/controllers/project-experience.js) and [HTTP route](../../src/dashboard/project-experience-routes.ts); see [UI regressions](../../test/project-experience-ui.test.js), [browser coverage](../../e2e/project-experience.spec.js) and the [guide](project-experience.md).

Opt-in [background memory learning](../../src/runtime/user-memory-learning.ts) persists accepted user inputs before execution, waits for idle, recovers interrupted work, bounds retries, validates evidence, and consolidates versioned entries. Dashboard owns its start/stop lifecycle. [Admission](../../src/runtime/user-memory-admission.ts) separates clear enduring self-descriptions from observations: weaker preferences need support from three distinct Tasks, and private candidates never enter foreground context. Validate [silent admission and persisted candidates](../../test/user-memory-admission.test.js).

Separate switches control memory use and automatic learning (both off for new profiles). Background work yields to foreground tasks, uses independent model/output settings and a persistent hourly request budget; see [scheduling regressions](../../test/user-memory-scheduling.test.js).

View memories opens one [profile editor](../../web/assets/controllers/user-memory-viewer.js) with revision-checked replacement and a total budget of 2000 characters. Internal evidence and legacy project boundaries remain protected, with a separate 6000-character limit for the complete injected section. See [storage regressions](../../test/user-memory-store-regressions.test.js) and [real Pi authorization](../../test/user-memory-authorization-pi.test.js). Validate [profile and concurrency](../../test/user-memory-profile.test.js), [learning/concurrency](../../test/user-memory-learning.test.js) and the [browser switch](../../e2e/user-memory.spec.js).

Cross-Task user memory is defined in [types](../../src/domain/user-memory.ts), [storage and context projection](../../src/runtime/user-memory-store.ts), and [tools](../../src/runtime/user-memory-tools.ts). Main uses the [.pi registration](../../.pi/runtime/tools/user-memory.ts) or Runtime RunService. Settings use [HTTP routes](../../src/dashboard/user-memory-routes.ts) and the [controller](../../web/assets/controllers/user-memory-settings.js). See [usage and boundaries (Chinese)](../user-memory.md); validate the `user-memory` Node tests and [browser settings test](../../e2e/user-memory.spec.js).

Foreground isolation uses [small activity leases and input intake](../../src/runtime/user-memory-foreground.ts), the store's profile projection, and a [final context budget check](../../src/runtime/user-memory-context.ts). In-flight checks avoid reparsing the full learning document; validate short input across hosts, connection switching and bounded intake in [isolation regressions](../../test/user-memory-isolation.test.js).

See [tool privacy](../../test/user-memory-tools-privacy.test.js) for disabled and project-scoped listing, and [context budgets](../../test/user-memory-context-budget.test.js) for tight budgets and real Pi requests.

[Original-request replay](../../src/runtime/main-request-retry.ts) refreshes only the memory projection while retaining other archived fields; validate [memory revocation and retries](../../test/user-memory-retry.test.js).

### Web search and scientific computing

Default web search and legacy selections are owned by [search configuration](../../src/runtime/web-search-config.ts), first-turn Main registration by [Pi web tools](../../.pi/runtime/tools/web-search.ts), source normalization by [web tools](../../src/tools/web-tools.ts) and the [Exa MCP adapter](../../src/tools/exa-search-provider.ts), and settings by the [search service](../../src/dashboard/web-search-settings.ts) and [shared controller](../../web/assets/controllers/web-search-settings.js). Verify [configuration](../../test/web-search-config.test.js), [MCP JSON/SSE/proxy/cancellation](../../test/exa-search-provider.test.js), [real Pi delegation/restart](../../test/web-search-pi.test.js), [browser settings and conversation](../../e2e/web-search-settings.spec.js), and [native anonymous search/settings restart](../../e2e/web-search-desktop.spec.js); update [configuration](configuration.md#web-search).

Versioned scientific catalogs and execution live in [science](../../src/tools/science/), experimental metadata in [analysis-catalog](../../src/tools/science/analysis-catalog.ts), astronomy metadata in [astronomy-catalog](../../src/tools/science/astronomy-catalog.ts), the three RuntimeTools in [scientific tools](../../src/tools/science-tools.ts), Run opt-in/version pinning and retry inheritance in [configuration](../../src/runtime/science-config.ts), and the Main wrapper in [.pi tools](../../.pi/runtime/tools/science.ts). Main and delegates share execution; disabled sessions retain their ordinary tools and skill catalog. Validate [original kernels](../../test/science-kernels.test.js), [experimental analysis](../../test/science-analysis.test.js), [astronomy](../../test/science-astronomy.test.js), [lifecycle](../../test/science-tools.test.js), [configuration](../../test/science-config.test.js), [real Pi](../../test/science-pi.test.js), [Dashboard retries/data workflow](../../test/science-main-retry.test.js) and [packaged closure](../../test/science-packaging.test.js); update the [guide](scientific-tools.md).

Science environment settings and explicit checks live in the [environment module](../../src/runtime/science-environment.ts), [HTTP routes](../../src/dashboard/science-settings-routes.ts) and [settings controller](../../web/assets/controllers/science-settings.js); reading/saving never probes Python. Native v4 molecular wrappers live in [molecular metadata](../../src/tools/science/chemistry-catalog.ts) and [kernels](../../src/tools/science/chemistry.py), using a separate pinned RDKit environment. Verify [RDKit numbers](../../test/science-chemistry.test.js) and [real browser settings](../../e2e/science-settings.spec.js), preserving v1–v3 provenance and Run selections.

The v5 crystal geometry and Scherrer tools live in [materials metadata](../../src/tools/science/materials-catalog.ts) and [materials kernels](../../src/tools/science/materials.py), using general Python's standard library. Verify [materials numbers](../../test/science-materials.test.js). Metrics must be positive definite and well conditioned; Scherrer uses Gaussian instrumental correction and nm units, and must not be presented as measured particle size. Existing v1–v4 catalogs and records retain their selection.

The v6 centroid and nominal Cl/C isotope tools live in [mass-spectrum metadata](../../src/tools/science/mass-spectrometry-catalog.ts) and [standard-library kernels](../../src/tools/science/mass_spectrometry.py). ## Three common change recipes

### Fix a user flow

Start from its reproduction/e2e/protocol test and trace requests/events to the state owner. Fix semantics there; routes map fields/status and UI handles presentation/interaction. Add a regression that reproduces the original failure, run related tests and verify, then corresponding browser tests for UI changes.

### Add an application or tool

Define resource format, revision, cancellation and failure guarantees first. Implement adapter/driver, discovery and domain tools, then workbench registration/UI. Shared protocols live in `applications/types.ts` or `software/contracts.ts`; HTTP/agent/UI use one operation implementation. Follow integration guidance and verify first-turn discovery, human/agent concurrent edits, conflict preservation and save/reopen.

### Split a large module

Identify state transitions, persistence, process ownership and rendering. Keep exports/formats/entrypoints compatible and migrate one responsibility with all consumers. Extracted modules cannot import their composition layer. Use architecture regression and existing behavior tests. Verify dependency direction and recovery behavior.

Review roles are in [module ownership](../module-ownership.md) (Chinese). This page gives navigation; root/scoped AGENTS provide constraints.
